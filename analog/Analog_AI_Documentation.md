# Analog Design — AI Usage Documentation

A running record of every use of AI assistance in the analog design work for
the ENGN 2912E SNN project: what was asked, what the AI did, what it produced,
and how far its output was checked. It is updated as the work continues.

- **Tool:** Claude Code (desktop app), model Claude Opus 5.5 (Anthropic)
- **User:** Ray Wu
- **Started:** 2026-10-25
- **Last updated:** 2026-11-05

## How AI is used in this project

| Category | What the AI does | What the AI does *not* do |
|---|---|---|
| Schematic / testbench review | Reads `.sch` files as text, works out connectivity from pin coordinates, points out wiring, topology and SPICE-setup errors | Edit existing schematics: changes to the user's schematics are made by the user in xschem. *Exception (2026-11-03, user approved):* the AI created the new `neuron_5khz*` files (entry 28). |
| Simulation debugging | Explains ngspice/xschem error messages and proposes fixes | Run xschem or ngspice without asking. *Exception (2026-11-03, user approved):* the AI ran xschem netlisting and ngspice in the user's iic-osic-tools container, with scratch output in the container's `/tmp` only (entry 28). |
| Results analysis | Reads `wrdata` text output (`*_tb.txt`) with short Python scripts and reports measured values (thresholds, step sizes, reset levels, timing) | Generate simulation data (except entry 28, as above) |
| Circuit explanation | Explains circuit operation (e.g. Indiveri et al. 2011, Figure 4) and design trade-offs | Choose final device sizes or architecture. *Exception:* entry 28, where the user asked the AI to size a copy of the neuron. |
| Estimates | Rough area and sizing estimates from rules of thumb | Provide sign-off numbers: no layout exists yet |
| Documentation | Writes and maintains Markdown logs | |

**Verification levels used below:**
- **Simulated:** numbers from ngspice runs the AI made itself (only entry 28, with the user's approval).
- **Analysed:** numbers computed by the AI from the user's own simulation output files.
- **Reasoned:** derived from reading files or from circuit theory; not simulated.
- **Estimate:** rule-of-thumb figure that needs checking against the PDK or a layout.

**30. Description of `_user_prompt` in `advisor.py`** *(Reasoned)*
- **Asked:** add a description of the user prompt to this file.
- **What it is:** each request to the model carries two messages. The *system prompt* (`SYSTEM_PROMPT`) is the fixed job description, the same every call. The *user prompt* is the specific question for this round, rebuilt each call by `_user_prompt(space, history, spec, n)` so it always includes the latest simulation results.
- **Inputs:** `space` (the tunable parameters and their bounds), `history` (every point simulated so far, with its measured metrics), `spec` (acceptable range per metric), and `n` (how many new candidates to ask for).
- **How it works:** it collects lines of text in a list, then joins them with line breaks into one block of text. It has four parts:
  1. **Parameters:** one line per knob with its minimum, maximum and grid step.
  2. **Spec:** one line per metric with its acceptable range.
  3. **Simulated points:** a comma-separated table with a header row (parameter names, metric names, `meets_spec`), then one row per simulated point with its values and pass/fail. If nothing has been simulated, it says so.
  4. **Request:** "Propose exactly n new candidates."
- **Example output** (two parameters, one metric, one simulated point):
  ```
  Parameters (name: lo .. hi, step):
    WP: 2.2e-07 .. 2e-06, step 5e-09
    WN: 2.2e-07 .. 2e-06, step 5e-09

  Spec (metric: acceptable range):
    vth_hi: 1.95 .. 2.05

  Simulated points:
    WP,WN,vth_hi,meets_spec
    4.4e-07,2.2e-07,1.5,False

  Propose exactly 4 new candidates.
  ```
- **Why a plain-text table:** it is compact, so many points fit in one request, and models read comma-separated tables reliably. `:.4g` rounds each number to 4 significant figures to keep it short.
- **AI found** in the user's version (lines 59–79):
  - Lines 78–79 (`Propose exactly…` and `return`) are indented inside the `else:` block. With an empty history, the function returns `None` instead of a prompt, so the first call of a run fails. They should be dedented to the level of `metrics = list(spec)`.
  - Line 74 uses `h['metrics'][m]`, which crashes with `KeyError` if a measurement failed. `h['metrics'].get(m, float('nan'))` prints `nan` instead.
  - Lines 61 and 64 format `p.lo` and `lo` without `:.4g`, unlike `hi`, so the bounds print inconsistently.
  - Line 69 typo: `(non yet)` should be `(none yet)`.
- **Not done by AI:** any change to `advisor.py`. The fixes are left to the user.
